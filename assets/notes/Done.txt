  - Before: `listenTogetherGuestLock` only guarded 3 controls (MiniPlayer skip + shuffle, Modern skip) — a guest could still seek, change repeat/speed, edit the queue, start radio/discover or skip from menus / library / notification and desync from the host; and a locally-paused guest was resumed by the host's next sync (the pause was never registered — see the root-cause fix below)

  - Phase 2 (central guard): new `ListenTogetherGuestGuardPlayer.kt` (`app.n_zik.android.listentogether`) — `ForwardingPlayer` whose policy reads `listenTogetherGuestLock` on every call: play/pause/prepare/setVolume/setPlayWhenReady + every reader/listener pass through; queue ops, seek ops, repeat/shuffle, playback speed and stop are fail-closed no-ops (any op not explicitly allowed is blocked) + throttled toast « The host controls playback » (2 s, string `listen_together_guest_blocked`) + `Timber.tag("LTGuestGuard")` log
  - Phase 3 (atomic tail + inert seek bar + stateful controls): a blocked head op (setMediaItem(s) + every seek op) arms a 50 ms tail-suppression window during which the 5 play-state pass-throughs are no-ops — a blocked skip no longer leaks its trailing `prepare()`/`playWhenReady = true` into playback (real human taps, >200 ms later, are never swallowed); the seek bar is fully inert for a locked guest — every scrub/seek attempt (all 7 `GetSeekBarType` variants) is answered with the throttled toast instead of a seek (supersedes the v2 "scrub stays visually interactive and snaps back" line); the bar itself keeps full opacity and size (`.alpha()` must not be applied to that subtree: alpha < 1 promotes content to a compositing layer sized to the layout bounds, which clipped the Wavy bar's overflow drawing — 15px-stroke wave + 15–20dp scrubber around a 6dp box — making it look "crushed"); stateful ON/OFF controls (radio, reorder lock/cadena, discover, loop, shuffle, video) are grayed + disabled for a guest and never toggle (cadena never unlocks); the sleep timer — which auto-stops the app after N minutes (session-level control, user decision 2026-09-29) — is locked for a guest too: MiniPlayer + ActionBar buttons grayed + disabled, player menu item grayed + blocked with the throttled toast (the internal timer is untouched: one started before joining a room still fires); the dead pause-based `playback/utils/SleepTimer` class was removed with its wiring (import, property, construction, crossfade listener swaps) — it had zero call-sites anywhere in the codebase (only the Binder `startSleepTimer` app-stop path is functional)
